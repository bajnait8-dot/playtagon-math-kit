# tools/ — инструменты разработчика, вне контракта

**Платформа этот каталог не читает, в модельный бандл он не входит.** Бандл §8.2 —
это содержимое `dice/server/` (SDK-канон: `model/` + `scenarios/` + `simulations/`
+ манифесты); здесь лежат скрипты сверки математики и локальное зеркало
платформенной сборки.

Симуляции на платформе исполняет платформенный воркер (§5.2), SDK-симуляции —
`dice/server/simulations/` (канон 13-simulation.md). Эти скрипты сохранены как
**независимая точка сверки**: их результат на той же паре (модель, конфиг) обязан
сходиться и с SDK-прогоном, и с платформенным.

## Скрипты сверки

Запускать из корня `UpdateGames` (зависимости ставит `npm install` в корне).

| Скрипт | Что проверяет |
|---|---|
| `verify-parity.ts` | новая модель ↔ старая: init, play на фиксированном сиде, verify, таблица выплат, статпрогон |
| `verify-knobs.ts` | значение из аргумента фабрики доезжает до математики; кривое значение — `ConfigValidationError`, а не тихий дефолт; два экземпляра с разными values в одном процессе |
| `verify-contract.ts` | `schema.json` ↔ `config.json` ↔ фактический выход модели |
| `verify-ev.ts` | EV полным перебором всех 10 000 исходов: точная сверка, не статистика |
| `build-mjs.mjs` | локальное зеркало платформенной сборки source-intake: esbuild от точки входа `schema.json#entry` → staging-срез `tools/dist/{schema.json, config.json, protocol.md, dist/index.mjs}` |
| `verify-mjs.ts` | сверка исполняемой формы: фабрика по `entry.export`, отпечаток выплат построенного `.mjs`, `err.name` исключений, две сессии в одном процессе |

Модель во всех скриптах поднимается как `createModel(values)` (§1.5.1): значения
ручек скрипты читают из `dice/server/config.json` сами (объявление значений) и
подают аргументом — код модели файл не читает. `verify-knobs.ts` не строит
песочниц; «объявленная ручка без значения» — падение, не дефолт (§5.1, Р-9).

```bash
npx tsx dice/tools/verify-parity.ts
npx tsx dice/tools/verify-knobs.ts
npx tsx dice/tools/verify-contract.ts
npx tsx dice/tools/verify-ev.ts
node dice/tools/build-mjs.mjs && npx tsx dice/tools/verify-mjs.ts
```

`verify-ev.ts` перебирает **каждый** из 10 000 исходов броска на сетке
`target × condition` и считает точное матожидание — оно обязано равняться
объявленному `rtp` при любом пороге и направлении. В конце печатается отпечаток
выплат: сумма `win` по всем исходам и сценариям. Любой сдвиг математики меняет
отпечаток, поэтому его достаточно сравнить одним числом.

Эталон на 2026-08-09 (`rtp = 0.99`): отпечаток **18986942**, EV = 0.990000 во всех
14 сценариях. Тот же отпечаток обязан давать и собранный `dist/index.mjs`
(`verify-mjs.ts` это проверяет).

`old-model/` — немодифицированная копия исходной модели
(`playtagon-dice/games/dice/server/model`) на момент переноса. Нужна только как
эталон для `verify-parity.ts`; в ней сохранены жёстко зашитые константы, включая
`RTP = 0.99`.

Прежние стенды из исходного `games/dice/server` (`dev.ts`, `simulate*.ts`,
`scenarios/`, `simulations/`) выросли в настоящие части SDK-контракта и живут в
`dice/server/` — см. `scenarios/index.ts`, `simulations/`, `dev.ts`, `simulate.ts`.
